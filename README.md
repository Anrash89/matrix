# Мандала — рабочий месяц

Личная матрица 9×9 для GitHub Pages. Один ориентир, 8 направлений, 64 действия.
Статический сайт без сервера, установки зависимостей и сборки.

## Быстрый запуск

1. Распакуйте архив. Для локального знакомства откройте **index.html**.
2. Для постоянного использования создайте репозиторий GitHub, например **mandala**.
3. Загрузите **содержимое** папки: index.html должен лежать в корне репозитория.
4. В **Settings → Pages → Build and deployment** выберите **Deploy from a branch**.
5. Укажите ветку **main**, папку **/(root)** и нажмите **Save**.
6. Дождитесь публикации. Адрес появится в том же разделе Pages.

Данные из локального файла не переносятся на GitHub Pages сами: сначала экспортируйте JSON,
на опубликованном сайте импортируйте его. Это также относится к смене домена и браузера.
На тарифе GitHub Free Pages доступен для публичных репозиториев.

## Рабочий месяц

Выберите дату старта. Первые 30 дней уже содержат 150 заданий с отдельными
шагами и критерием готовности. Три задачи про бизнес, одна про движение и одна
про восстановление. Задачи можно посмотреть заранее. Отметки доступны для
текущего дня и прошедших дней.

В «Воронке» заполняются итоги за день по каналу: обращения, ответы, демо и
предложения. В журнале оплат вводятся фактические платежи и возвраты с
указанием сервиса и источника. «Динамика» строит графики из этих данных.
Выручка считается до расходов и налогов. Архив и прошлый план входят в
накопительный показатель первого миллиона.

В **SALES.html** есть практическая инструкция поиска с нуля, запросы, критерии
отбора и готовые сообщения. После работы над месяцем запишите выводы в
«Отчётах» и скачайте **mandala-report-….json**. В отчёт входят отметки задач,
выручка, возвраты, воронка и разбивка по источникам и сервисам. Отдельные
пометки к оплатам остаются в полной резервной копии.

Пришлите отчёт в чат и запросите следующий план в формате
**mandala-month-plan JSON**. После окончания периода загрузите полученный
файл в «Отчёты → Загрузить следующий план» и выберите дату старта.
Итог закрытого месяца останется в архиве. Перед сменой цикла сохраните
отчёт или полную резервную копию, если нужны отдельные старые записи.

Формат файла следующего плана: объект с type = mandala-month-plan, version = 1,
title, target в целых рублях и days — массив из 30 массивов по 5 задач.
В каждой задаче title, steps (массив строк), done (текст результата).
Порядок: поиск клиентов, демо и продукт, деньги и развитие, движение,
восстановление. Пример содержимого лежит в plan-data.js.

Старые документы и матрица сохраняются. Задания прежнего 90-дневного цикла
остаются в полной резервной копии. Прежние платежи входят в накопительную
выручку. Для нового 30-дневного периода приложение предложит дату после
последнего ранее внесённого платежа, чтобы не дублировать сумму.

- Крупные карточки направлений на телефоне; полная карта доступна с прокруткой.
- Редактирование всех текстов, сроков и статусов.

## Первая матрица

Главная цель — первый миллион с собственных сервисов, первый измеримый рубеж —
100 000 ₽ поступлений за 30 дней. Матрица помогает вести общие направления.
План на 30 дней содержит конкретные ежедневные задачи.

**Начальный пример находится в seed.js и будет виден посетителям сайта и репозитория.**
В нём нет паролей, адресов или реальных финансовых показателей. Личные правки сохраняются
в вашем браузере или закрытом Firestore, а не в GitHub. Не загружайте JSON с личными заметками
в публичный репозиторий. Если стартовый пример не должен быть публичным, измените seed.js
перед публикацией; личную матрицу после этого можно импортировать JSON-файлом.

## Облако

Откройте **SETUP.html** — там подробная инструкция без командной строки.
Без Firebase весь локальный функционал работает. Облачный проект пользователь создаёт
в своём Google-аккаунте. Здесь он не создан и реальная авторизация не проверялась.

Приложение использует Firebase Web SDK 13.3.0 через официальный CDN (загружается только
при подключении облака), Authentication Google и Cloud Firestore Standard.
Внешний шрифт Inter загружается из Google Fonts; при недоступности используется системный.

Синхронизация **по кнопке**, не в реальном времени. Порядок на другом устройстве:
войти в тот же проект и аккаунт → загрузить из облака → редактировать → сохранить в облако.
При конфликте запись блокируется. Экспортируйте локальный вариант, загрузите облачный,
перенесите нужные изменения и сохраните. Автоматического объединения нет.
Изменения после выхода из аккаунта остаются локально.

## Ограничения

- Локальные данные привязаны к браузеру и адресу. Очистка данных, приватный режим
  или ограничения хранилища могут привести к потере. Используйте JSON-копии.
- Это не полная система Харады, а практическая адаптация матрицы Мандалы.
- Выполненные шаги не равны достигнутому доходу: оба показателя учитываются отдельно.
- Нет фоновых уведомлений, банковской интеграции и автоматического учёта привычек.
- Одна матрица на браузер / аккаунт проекта, до 200 записей рефлексии.
- Начальная конфигурация Firebase хранится только на устройстве. На новом устройстве
  её нужно вставить снова (это идентификаторы веб-приложения, не сервисный ключ).
- Google-вход требует HTTP(S), сети и разрешённого всплывающего окна. Для телефона
  откройте сайт в обычном Safari/Chrome, не во встроенном браузере Telegram.
- Проверка локальных конфликтов предотвращает обычную перезапись между вкладками,
  но localStorage не является транзакционной базой. Работайте в одной вкладке.
- Облачные права и фактическую запись нужно проверить после настройки проекта.

## Файлы

- index.html, styles.css, app.js — интерфейс и работа приложения.
- seed.js — стартовый редактируемый пример.
- plan-data.js — 150 заданий, plan.js — даты, отметки, касса, воронка и отчёт.
- daily.js — список проектов и совместимость со старыми дневными записями.
- SALES.html — тактика продаж и источники лидов.
- core.js — схема, проверка резервной копии, структура матрицы.
- firestore.rules — правила с доступом только одному UID.
- SETUP.html — наглядная инструкция запуска и облака.
- tests/core.test.cjs — проверки структуры и импорта. Запуск: **node --test tests/core.test.cjs**.
