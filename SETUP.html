Твоя матрица.
На любом устройстве.

Сначала опубликуй сайт. Облако можно подключить позже: сохранение в браузере и резервные JSON-копии уже работают.

01 / GITHUB PAGES

Опубликовать сайт

  1. Создай репозиторий на GitHub, например mandala. Для GitHub Free используй публичный репозиторий.
  2. Загрузи файлы из архива. index.html должен находиться в корне, рядом с app.js, seed.js, core.js, styles.css и папкой assets.
  3. Открой Settings → Pages. В разделе Source выбери Deploy from a branch, ветку main, папку /(root). Нажми Save.
  4. Когда публикация закончится, открой адрес из Pages. Матрица уже готова к работе.

Начальный пример в seed.js публичен вместе с сайтом. Твои последующие изменения остаются в браузере и закрытой базе. Не загружай личные JSON-копии в публичный репозиторий.

02 / FIREBASE

Создать своё облако

  1. Открой Firebase Console и создай проект. Analytics для этой матрицы не нужен.
  2. Выбери бесплатный план Spark. Для личной матрицы начальной квоты обычно достаточно; подключать оплату ради этого приложения не требуется.
  3. В обзоре проекта добавь веб-приложение (значок </>). Назови его «Мандала». Firebase Hosting не нужен: сайт будет на GitHub Pages.
  4. Скопируй объект firebaseConfig. Нужны как минимум apiKey, authDomain, projectId, appId. Не скачивай сервисный ключ.
  5. В Authentication → Get started → Sign-in method включи провайдер Google, укажи контактную почту и сохрани.
  6. В Authentication → Settings → Authorized domains добавь домен сайта без протокола и пути, например имя-пользователя.github.io. Если используешь свой домен, добавь его.
  7. В Firestore Database → Create database создай базу Standard с ID (default) в Production mode. Выбери доступный регион. Режим test не нужен.

Firestore предоставляет бесплатную квоту. Актуальные лимиты проверяются в консоли и официальной документации. Подключение облака потребует сети; локальные данные работают независимо от него.

03 / ЛИЧНЫЙ ДОСТУП

Разрешить доступ только себе

  1. На своём опубликованном сайте открой значок облака → «Данные и облако».
  2. Вставь конфигурацию. Можно вставить JSON или блок const firebaseConfig = { ... }; с двойными кавычками у значений.
  3. Нажми 1. Подключить проект, затем 2. Войти через Google. Разреши всплывающее окно, если браузер его блокирует.
  4. После входа приложение покажет UID. Его также можно скопировать в Firebase → Authentication → Users.
  5. Открой файл firestore.rules. Замени REPLACE_WITH_YOUR_FIREBASE_UID на свой UID, сохранив кавычки.
  6. Вставь весь текст правил в Firestore Database → Rules и нажми Publish. Пока UID не заменён, доступ запрещён всем.
  7. В матрице нажми Сохранить в облако. Должно появиться сообщение о сохранённой версии 1.

Правила разрешают чтение и запись только твоему UID в одном документе users/UID/matrices/main. Другие аккаунты не смогут прочитать или изменить его. Настройки доступа проверяет Firebase, а не только интерфейс сайта.

04 / ТЕЛЕФОН И КОМПЬЮТЕР

Продолжить на другом устройстве

  1. Открой тот же опубликованный сайт в обычном Chrome или Safari.
  2. Открой «Данные и облако», вставь конфигурацию того же Firebase-проекта, подключи его и войди в тот же Google-аккаунт.
  3. Нажми Загрузить из облака. При первом входе приложение не станет молча затирать локальный пример.
  4. Редактируй матрицу. Локально изменения сохраняются сразу после формы / отметки.
  5. Перед переходом на другое устройство нажми Сохранить в облако. На другом устройстве нажми Загрузить из облака.

Синхронизация ручная. Если другая версия уже сохранена, запись остановится. Скачай свой локальный JSON, загрузи актуальную матрицу, перенеси нужные изменения и сохрани. Это защищает от случайной потери правок.

Начать рабочий месяц

  1. На вкладке «Месяц» нажми «Начать месяц» и выбери дату.
  2. Раскрывай карточки задач. В каждой шаги и критерий готовности.
  3. В «Воронке» записывай итоги по каналам, а через «Записать оплату» вноси реальные платежи и возвраты. Динамика строится по введённым цифрам.
  4. В конце месяца скачай JSON во вкладке «Отчёты» и пришли его в чат. Готовый следующий план загрузи в этой же вкладке. Перед переходом можно скачать полную резервную копию.

Если что-то не подключается

  • unauthorized-domain: добавь точный домен сайта в Authorized domains.
  • permission-denied: проверь UID, правила и что нажал Publish.
  • popup-blocked: разреши всплывающее окно и нажми вход ещё раз. Во встроенных браузерах соцсетей Google-вход может не работать.
  • Сеть или лимит: используй локальную матрицу и JSON. Сохранение в облако можно повторить позднее.
  • После обновления сайта старый вид: обнови страницу с очисткой кэша. Не очищай данные сайта: там локальная матрица.

Проверка после подключения

Добавь заметку, сохрани в облако, затем загрузи матрицу на втором устройстве и проверь заметку. После этого проверь сохранение в обратную сторону. Без твоего Firebase-проекта реальный вход, правила и передачу между устройствами проверить невозможно.
